# Authkestra Agent Rules

- **Typestate Builder Pattern**: Use `Authkestra::builder()` which enforces compile-time availability of methods (e.g., `create_session` only exists if `session_store` is provided).
- **RFC-001 Migration (complete)**: `authkestra-core`, `authkestra-flow`, `authkestra-token` and `authkestra-session` no longer exist — they were merged into `authkestra-engine`. Target `Engine` and the plugin interfaces (`AuthMethod`, `Flow`) there. If a doc or comment still names one of those crates, it is stale.
- **Trait Objects vs Generics**: Prefer `Box<dyn Trait>` (e.g., `Box<dyn AuthMethod>`) over generics for I/O bound paths to optimize compilation time and DX.
- **Framework Agnostic**: The core must remain framework-independent. Axum/Actix integrations live in separate adapter crates (`authkestra-axum`, `authkestra-actix`) and use extractors (`AuthSession(session)`).
- **Stateless OAuth**: Store OAuth `state` and `nonce` in encrypted cookies, never in the database.
- **OIDC Discovery**: Cache discovery documents via background `tokio::spawn` tasks, avoid per-request fetching.
- **Database Agnosticism**: Never enforce schemas; always define data access via traits (`KvStore`, `SessionStore`, `CredentialStore`, `authkestra-op`'s `OpStore`). There is deliberately no user/account trait - the host application owns that data.
- **Definition of Done (DoD) - Tracing**: Every new handler, endpoint, or significant logical branch MUST include adequate `tracing` instrumentation (`tracing::debug!`, `tracing::info!`, `tracing::warn!`, `tracing::error!`) to ensure request flows and errors are fully visible in production without requiring code changes.
- **Definition of Done (DoD) - Framework Wiring**: Every new handler added to `authkestra-op` MUST have a corresponding route wired in both `authkestra-axum/src/op.rs` and `authkestra-actix/src/op.rs` in the same PR.
- **Pull Request Checks**: When opening a Pull Request or pushing commits, always ensure that CI passes locally by running the exact commands from `.github/workflows/ci.yml` — `cargo fmt --all -- --check`, `cargo clippy --workspace --all-features -- -D warnings`, `cargo test --workspace --all-features`, `cargo llvm-cov --workspace --all-features --lcov --output-path lcov.info --fail-under-lines 84`, and `cargo deny check`. Verify there are no merge conflicts before creating or pushing to the PR.
- **Examples Live in the Facade**: Every runnable example lives in `crates/authkestra/examples/`, named `<framework>_<scenario>.rs` (e.g. `axum_op_server.rs`), and runs as `cargo run -p authkestra --example <name> --all-features`. The only exceptions are the four framework-free protocol examples in `crates/authkestra-engine/examples/` (`client_credentials`, `device_flow`, `sd_jwt`, `totp_webauthn`). Do not add examples to the adapter crates.
- **Docs Are Not Compiled**: Markdown under `README.md`, `crates/*/README.md` and `docs/` is not checked by CI, so it drifts silently. When you change a public API name, signature, route path, or feature flag, grep those trees for the old spelling in the same PR. The prose documentation site (`Authkestra/docs`, deployed to docs.authkestra.com) and landing page (`Authkestra/landing`, deployed to authkestra.com) live in their own repositories and are *not* checked out here — when a change alters a public API, those repos need their own PRs, and nothing in this repository's CI will tell you that you forgot.
- **Repository Hygiene (Scratch Files)**: Never commit throwaway refactoring scripts, migration tools, or scratch files to the repository. Write them to your sandboxed `scratch/` directory or a `.gitignore`d path. Avoid using `git add .` blindly to prevent accidentally staging temporary files.
